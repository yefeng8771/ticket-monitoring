## 0. 不可违反的边界

- 不自动破解、绕过或规避验证码 / 滑块 / 反机器人风控；只做真实识别、状态暴露、可见窗口和人工接管。
- 不伪造航班、价格、截图、进度、原始响应或登录有效证据；缺数据就标未采/未供/失败。
- 不在页面、日志、证据导出或发行包泄露 Cookie、Token、密码、会话文件。
- 不重置工作区、不覆盖并行会话改动；集中文件 `webui.py` 只由主控集成。
- 只有拿到真实明细才算“明细成功”；日历价、旧缓存补位、空结果、登录失败分别归类。
- 未经授权不向真实外部收件人发送测试消息。

## 2. 本轮六个优先项

### P1 实时探针全过程可观察
- 启动即出现任务摘要并自动展开；收起不停止任务，重开不重复提交。
- 按“任务 → 航线/日期 → 渠道”展示真实阶段、状态、耗时、结果类型/数量、重试、阻塞原因。
- 阶段必须来自真实事件（排队、会话、请求、响应、解析、去重、结果、完成）；禁止假进度/固定百分比/预计完成时间。
- 增量结果先到先展示；支持筛选、定位、详情、取消、断线重连、失败项单独重试。
- 取消必须传到后端；晚到响应不得污染新任务；成功结果保留。

### P2 首次进入不被隐性筛选清空
- 建立“页面—数据源—上下文—加载时机—刷新—离开清理”对应表。
- 干净首次进入使用中性条件：全部渠道、关键词空、只看达标/隐藏补位关闭；不自动继承跨用户/航线/模式旧条件。
- 显式深链和主动恢复快照尊重原条件；恢复必须提示“已恢复上次筛选”和完整生效条件。
- 慢响应、失败恢复、A→B→A 切换和旧响应不得覆盖新上下文。

### P3 探针草稿 / 已提交任务 / 结果筛选隔离
- 草稿只属于待提交表单；修改日期/渠道不得立即改变当前结果、镜像或筛选。
- 提交后任务快照固定出发日期和请求渠道；结果筛选只过滤本任务已返回记录。
- 清除结果筛选不得改任务日期/请求渠道；不能为了非空偷偷换条件。

### P4 计数与空态
- 区分跨日期总量、所选日期量、筛选后可见量、唯一航班、渠道报价、本轮/历史。
- 不得把“航线跨日期 503 行”说成“所选日期 503 行”；只有当前范围有数据被筛掉才叫“筛选隐藏”。
- 空态分别表达：未采、原站无票、请求失败、所选日期无数据、筛选为空。

### P5 检索页布局
- 首屏顺序：查询与任务入口 → 当前执行反馈 → 结果筛选与列表/详情。
- 初次探针可直接操作；收起后紧凑单行，展开后查询控件与渠道紧邻对齐。
- 减少空日期卡、重复零值卡和无用途留白；日期带全未采时收敛为范围+说明+查询入口。
- 生效条件始终可见；编辑器可收起；125%/200% 缩放和窄屏主要动作可达。

### P6 渠道能力 / 会话 / 本次产物分离
- 三件事分别显示：登录态已保存、会话验证有效、本次真实明细成功。
- 保存后显示“已保存，验证中”，验证完成自动更新；不以超时/空结果推断重登。
- 飞猪、同程新登录态必须被下一次真实请求使用；日历价不能标成明细成功。
- 本次截图中的“国际数据能力”混写必须拆开；能力标签不能代替本次结果。
